## מה זה?

בשיעורי ה-DB למדנו שנתונים רלציוניים מאורגנים בטבלאות — שורות ועמודות. כשרוצים **להציג** נתונים כאלה בעמוד אינטרנט (למשל, טבלת מחירים, לוח זמנים, תוצאות חיפוש), HTML נותן תגיות ייעודיות לכך: `<table>`. **חשוב**: בימי HTML הראשונים, מפתחים השתמשו בטבלאות **לפריסת עמוד שלם** (layout) — זה נחשב היום לשימוש שגוי; טבלאות מיועדות **רק** לנתונים טבלאיים אמיתיים.

## מילות מפתח שחשוב לזכור

• `<table>` — האלמנט העוטף שמכיל את כל הטבלה

• `<tr>` (table row) — שורה בודדת בטבלה

• `<td>` (table data) — תא בודד עם נתון, בתוך שורה

• `<th>` (table header) — תא כותרת (בדרך כלל בשורה הראשונה או עמודה ראשונה) — מודגש כברירת מחדל ומסומן סמנטית ככותרת

• `<thead>` / `<tbody>` — מחלקים את הטבלה לאזור כותרות (`thead`) ואזור נתונים (`tbody`) — עוזר גם לקריאות וגם לנגישות

```html
<table>
  <thead>
    <tr>
      <th>שם</th>
      <th>תפקיד</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>דנה</td>
      <td>מפתחת</td>
    </tr>
    <tr>
      <td>יוסי</td>
      <td>מעצב</td>
    </tr>
  </tbody>
</table>
```

## הסבר עיקרי

th מול td — ההבדל קריטי לנגישות: `<th>` מסמן תא ככותרת עמודה/שורה — קורא מסך מבין שזו "כותרת" ויכול "להזכיר" אותה למשתמש כשהוא עובר על תאי נתונים (`<td>`) בהמשך — כך שהמשתמש תמיד יודע לאיזו עמודה שייך כל נתון, גם בלי לראות את הטבלה חזותית.

thead/tbody כארגון סמנטי — בדיוק כמו ש-Semantic HTML (שיעור קודם) חילק עמוד ל-`header`/`main`/`footer`, `thead`/`tbody` מחלקים טבלה לאזור כותרות ואזור נתונים — עוזר גם לקוראי מסך וגם לספריות JavaScript (בהמשך הקורס) שצריכות "לדעת" אילו שורות הן כותרת ואילו הן נתונים.

למה לא להשתמש בטבלאות ל-layout — נניח שרוצים לפרוס עמוד לשלוש עמודות זו לצד זו. שימוש ב-`<table>` לכך (כמו שנהגו בעבר) "משקר" סמנטית — קורא מסך "יחשוב" שיש כאן נתונים טבלאיים אמיתיים, ויתבלבל. פריסת עמוד היא תפקיד CSS (Flexbox/Grid, ביחידת CSS הבאה) — לא HTML.

## יתרונות

תגיות ייעודיות (`th`/`td`/`thead`/`tbody`) נותנות מבנה ברור ונגיש לנתונים טבלאיים אמיתיים; קוראי מסך יודעים "להקריא" נתונים בהקשר הכותרת המתאימה; דפדפנים מציירים טבלאות (יישור עמודות, גבולות) אוטומטית.

## חסרונות

טבלאות לא-רספונסיביות (רחבות) יכולות "לגלוש" ממסך מובייל צר בלי טיפול נוסף (CSS); טבלאות מקוננות (טבלה בתוך טבלה) פוגעות משמעותית בנגישות ובקריאות הקוד.

## נקודות חשובות למבחן / ראיון עבודה

• `<table>` מיועדת **רק** לנתונים טבלאיים אמיתיים, לא לפריסת עמוד

• `<th>` מסמן כותרת (עמודה/שורה); `<td>` מסמן תא נתונים רגיל

• `<thead>`/`<tbody>` מחלקים טבלה לאזור כותרות ואזור נתונים

• שימוש בטבלאות ל-layout נחשב לפרקטיקה שגויה ומיושנת

## טעויות נפוצות

• שימוש ב-`<td>` בכל מקום במקום `<th>` לכותרות — קורא מסך לא מבין מה כותרת ומה נתון

• שימוש בטבלאות ל-layout עמוד כללי — פוגע בנגישות ובסמנטיקה

• שכחת `<thead>`/`<tbody>` בטבלאות גדולות — הקוד עדיין "עובד" ויזואלית, אבל פחות נגיש וקריא

## סיכום

`<table>` עם `<tr>`/`<th>`/`<td>` מציג נתונים טבלאיים אמיתיים — שורות ועמודות, כמו טבלת SQL. `<th>` מסמן כותרות (קריטי לנגישות); `<thead>`/`<tbody>` מארגנים את הטבלה סמנטית. טבלאות **לא** מיועדות לפריסת עמוד — זה תפקיד CSS.

## תרגילים

### תרגיל 1 — טבלה בסיסית

**המשימה:** בנו טבלה עם 3 עמודות (שם, גיל, עיר) ו-3 שורות נתונים, עם `<th>` נכון לכותרות.

**בדיקה:** הטבלה מוצגת בדפדפן עם כותרות מודגשות בשורה הראשונה, ונתונים רגילים מתחת.

### תרגיל 2 — thead/tbody

**המשימה:** הוסיפו לטבלה מהתרגיל הקודם `<thead>` סביב שורת הכותרות ו-`<tbody>` סביב שורות הנתונים.

**בדיקה:** בבדיקת DevTools (Elements), הכותרות מקוננות תחת `<thead>` והנתונים תחת `<tbody>`, לא כולם תחת `<table>` ישירות.

### תרגיל 3 — טבלה מרובת עמודות

**המשימה:** הרחיבו טבלה קיימת ל-5 עמודות ו-5 שורות עם נתונים אמיתיים (למשל: מוצרים ומחירים).

**בדיקה:** כל שורה מכילה בדיוק 5 תאי `<td>` (תואם למספר העמודות בכותרת) — לא יותר ולא פחות.

## פרויקט מסכם

**המשימה:** בנו טבלת "ציונים" לכיתה, עם נתונים אמיתיים.

**דרישות:**
1. `<thead>` עם כותרות: שם תלמיד, מקצוע, ציון
2. `<tbody>` עם לפחות 5 שורות נתונים
3. שימוש נכון ב-`<th>`/`<td>` — לא `<td>` בכל מקום
4. הוסיפו שורת "סיכום" בתחתית (למשל ממוצע) — חקרו האם היא שייכת ל-`<tbody>` או שצריך `<tfoot>`

**בדיקה:** הטבלה מוצגת נכון בדפדפן; בדיקה ב-DevTools (Accessibility tree) מזהה את `<th>` ככותרות עמודה.
