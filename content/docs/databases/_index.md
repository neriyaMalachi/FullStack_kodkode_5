## מה זה?

כל אפליקציה אמיתית צריכה לשמור מידע לאורך זמן — משתמשים, פוסטים, הזמנות — ובסיסי נתונים הם הכלי לכך. בקטגוריה הזו לומדים את שתי הגישות המרכזיות לאחסון מידע: בסיסי נתונים יחסיים (SQL) שמארגנים מידע בטבלאות עם קשרים מוגדרים היטב, ובסיסי נתונים מסוג NoSQL כמו MongoDB שמאחסנים מסמכים גמישים יותר. מבינים מתי כל גישה מתאימה, ואיך לחבר את השרת שבנינו בעבר בפועל לבסיס נתונים אמיתי, מקומי או בענן.

## מה הולכים ללמוד

- **Relational vs NoSQL** — מתי עדיף בסיס נתונים יחסי ומתי בסיס נתונים מסוג מסמכים
- **SQL Basics** — איך כותבים שאילתות בסיסיות לשליפה, הוספה, עדכון ומחיקה של מידע
- **SQL Joins** — איך משלבים מידע מכמה טבלאות לשאילתה אחת
- **DB Design** — איך מתכננים סכמת טבלאות וקשרים כך שהמידע יישאר עקבי ויעיל
- **Supabase (hosted Postgres)** — איך מריצים בסיס נתונים יחסי מנוהל בענן בלי להתקין שרת בעצמנו
- **SQL from Node** — איך מתחברים לבסיס נתונים יחסי מתוך קוד Node.js ומריצים שאילתות מהשרת
- **MongoDB Basics** — איך שומרים ושולפים מסמכי JSON בבסיס נתונים מסוג NoSQL
- **MongoDB Operators** — איך מסננים ומעדכנים מסמכים בעזרת אופרטורים ייעודיים
- **MongoDB Atlas (cloud)** — איך מריצים MongoDB בענן בלי התקנה מקומית
- **MongoDB Compass (GUI)** — איך צופים ועורכים מידע ב-MongoDB בממשק גרפי נוח
- **Mongoose (ODM)** — איך מגדירים סכמות ומודלים ומתחברים ל-MongoDB בצורה מסודרת מתוך Node
- פרויקט מסכם — בניית אותו מודל נתונים של בלוג פעמיים, פעם אחת יחסית ופעם אחת ב-MongoDB, כדי להשוות בין הגישות בפועל

## למה זה חשוב

בלי בסיס נתונים, כל מידע נעלם ברגע שהשרת נסגר — אין משתמשים, אין תוכן, אין הזמנות. הנושאים בקטגוריה הזו מאפשרים לבנות אפליקציות שבאמת "זוכרות" מידע לאורך זמן, ולבחור את סוג בסיס הנתונים המתאים לכל פרויקט לפי הצרכים שלו. זהו אחד הכישורים המרכזיים ביותר של מפתח Backend, ונדרש כמעט בכל משרה — כולל היכולת לתקשר עם צוותי DevOps ו-DBA שמנהלים את התשתית הזו בסביבת פרודקשן.
