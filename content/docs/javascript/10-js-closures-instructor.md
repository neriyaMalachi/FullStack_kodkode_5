משך: 2 שעות אקדמיות (90 דקות).

מטרת השיעור: הסטודנטים יבינו למה פונקציה רגילה לא יכולה "לזכור" state בין קריאות, ואיך Closure פותר את זה — כתוצאה הגיונית של Lexical Scope, לא כ"קסם".

בסוף השיעור הסטודנטים צריכים: להסביר למה let count=0 בתוך פונקציה מתאפס בכל קריאה, לכתוב Factory Function שמחזירה state פרטי, ולזהות ולתקן את הבאג הקלאסי של var בלולאה עם setTimeout.

דגש קריטי: לעולם אל תגידו את המילה "closure" לפני שהוצגה הבעיה הקונקרטית. הסדר: הבעיה → הבעיה בקוד → הפתרון → ורק אז ההגדרה.

## דגשים להעברת השיעור

- קודם הבעיה, אחר כך ההגדרה — הריצו makeCounter() פעמיים חי מול הסטודנטים.

- ההדגמה החיה החשובה ביותר — c.inc(); c.get() — הראו ש-c.n הוא undefined.

- Lexical Scope לפני "closure" כמושג מופשט — "אל תגידו 'זה קסם'."

- IIFE מוצג כפתרון אמיתי (Module Pattern), לא כהרחבה מיותרת.

- הבאג של var — הריצו את שתי הלולאות חי בקונסול, תנו לנחש קודם.

## מושגים

- **Lexical Scope:** פונקציה "רואה" את המשתנים של הסביבה שבה הוגדרה — לא שבה נקראה.

- **Closure:** פונקציה פנימית שמשמרת גישה לסביבת ה-scope שבה נוצרה.

- **Factory Function:** פונקציה שמחזירה פונקציה (או object של פונקציות) — כל קריאה יוצרת closure עצמאי.

- **Private State:** משתנה שניתן לגשת אליו רק דרך הפונקציות שנוצרו ב-closure שלו.

- **IIFE:** פונקציה שמוגדרת ומופעלת מיד; משמשת ל-Module Pattern.

- **Module Pattern:** שימוש ב-closure ליצירת מודול עם state פרטי ו-API ציבורי מוגבל.

## תרגיל חשיבה

- **נושא:** כמה counters יש כאן?

- נציג קוד שיוצר שני counters מאותה makeCounter() ומפעיל כל אחד מספר שונה של פעמים.

- נשאל: "כשמדפיסים את ה-counter הראשון — מה יוצג? ושל השני?"

- **מהלך:** הצגת הקוד, ניחוש + נימוק, הרצה, גילוי שכל קריאה יוצרת סביבה חדשה ונפרדת.

- המדריך יסכם: "כל קריאה לפונקציה החיצונית פותחת סביבה חדשה — זו הסיבה שה-state תמיד עצמאי בין instances."
