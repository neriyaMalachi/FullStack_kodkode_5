משך: 2 שעות אקדמיות (90 דקות).

מטרת השיעור: הסטודנטים יפנימו שקוד טוב הוא לא קוד שעובד — אלא קוד שאנשים אחרים (ועצמך בעוד חודש) יוכלו לקרוא ולתחזק. ויישמו עקרונות בסיסיים שמשנים את האיכות מיד.

בסוף השיעור הסטודנטים צריכים: לשנות שמות ל-Meaningful Names, לפצל פונקציה ל-Single Responsibility, ולהמיר if מקונן ל-Early Return / Guard Clause.

דגש קריטי: Clean Code הוא לא נושא תיאורטי — הסטודנטים צריכים לצאת עם קוד ספציפי ביד שהם כתבו ואז שיפרו.

| שיתוף וסיכום | 10 דקות | השוואה לפני ואחרי |

## דגשים להעברת השיעור

- Meaningful Names — אם צריך comment להסביר את שם המשתנה, שנו את השם.

- Magic Numbers — מה זה 18? מה זה 1000? const ADULT_AGE = 18 — עכשיו ברור.

- Guard Clause — הדגימו את "פירמידת הדום" קודם, ואחר כך מה קורה אחרי Guard Clauses.

- DRY — שלוש שורות זהות? עטפו בפונקציה. אל תאפשרו לסטודנטים להרגיש "אבל זה עובד".

- מתי Comment — Comment מסביר WHY, לא WHAT. WHAT — השמות אמורים לענות על זה.

## מושגים

- **DRY (Don't Repeat Yourself):** כל חתיכת לוגיקה קיימת במקום אחד בלבד.

- **Single Responsibility:** כל פונקציה עושה דבר אחד בלבד.

- **Meaningful Names:** שמות שמסבירים כוונה.

- **Magic Number:** ערך מספרי בקוד ללא הסבר.

- **Early Return:** החזרת ערך בהקדם כדי להימנע מ-if מקונן.

- **Guard Clause:** בדיקת תנאי שגיאה/edge case בתחילת פונקציה.

- **Refactoring:** שיפור מבנה קוד מבלי לשנות את התנהגותו.

- **Comment WHY not WHAT:** Comments צריכים לספר את הסיבה לבחירה.

## תרגיל חשיבה

- **נושא:** כמה בעיות יש כאן?

- נציג פונקציה ארוכה של 20 שורות עם: שם לא ברור, Magic Numbers, if מקונן, ולוגיקה שעושה שלושה דברים.

- נשאל: "כמה בעיות Clean Code יש כאן? מה הייתם משנים ראשון?"

- **מהלך:** קריאת הקוד, זיהוי בעיות, סדר עדיפויות, שיפור שלב אחר שלב.

- המדריך ישאל בסוף: "איזה שיפור נתן את ה-impact הגדול ביותר לקריאות?"
